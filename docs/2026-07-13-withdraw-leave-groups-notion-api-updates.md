## 1. `DELETE /api/users/me` — 회원 탈퇴  ⚠️ 동작 변경(스키마 변화 없음)

**요청/응답 스펙 변화 없음** (기존대로 인증 필요, 204 No Content).

**추가 동작:** 탈퇴하면 이제 그 사용자가 속한 **모든 모임에서 "나간 것"으로 처리**된다.
(모임 나가기 API와 동일한 규칙 — 멤버십에 나간시각(`left_at`)을 기록)

기존에는 탈퇴해도 모임 멤버십을 건드리지 않아 탈퇴자가 계속 "활성 멤버"로 취급됐고,
아래 문제가 있었다. 이번 변경으로 모두 해결된다.

- **모임 멤버 목록**에서 탈퇴자가 즉시 사라진다(기존: 탈퇴 전 닉네임 그대로 남아 있었음).
- **회차 참여 인원 집계**에서 탈퇴자가 빠진다 → 남은 인원이 전원 사진 업로드하면
  **조기 마감이 정상 동작**한다(기존: 탈퇴자 때문에 인원이 안 맞아 조기 마감이 안 됨.
  24시간 자동 마감은 원래 정상이었음).
- 탈퇴자가 그 모임의 **마지막 활성 멤버였다면 모임도 자동 삭제**된다(soft delete,
  모임 나가기와 동일 규칙).

**유지(변화 없음):**
- 탈퇴 사용자의 **사진(shot) 등 데이터는 삭제하지 않는다.**
- 탈퇴 후 **5일 보존 → 완전 삭제** 정책 그대로. (멤버십·알림·사용자 행은 5일 뒤 스케줄러가 물리 삭제)

> 명세 비고란 권장 문구: "회원 탈퇴 시 속한 모든 모임에서 자동 탈퇴 처리(멤버 목록·회차 집계에서 제외),
> 마지막 멤버였다면 모임 자동 삭제. 데이터는 5일 보존 후 완전 삭제."

## 2. (참고) 영향 받는 조회 API — 표기 확인용, 스키마 변화 없음

탈퇴자의 `left_at`이 채워지면서 **기존 "활성 멤버(left_at IS NULL)만 노출" 규칙**에 의해
아래 응답에서 탈퇴자가 자연스럽게 빠진다. 별도 필드/파라미터 변경은 없다.

| API | 변화 |
|---|---|
| `GET /api/groups/{groupId}` (모임 상세 — 멤버 목록) | 탈퇴자 제외 |
| `GET /api/cycles/{cycleId}/shots` (회차 사진 목록 — 멤버별) | 탈퇴자 제외(사진 기록은 DB에 남지만 목록엔 미노출) |
| 모임 목록/미리보기의 멤버 수 카운트 | 탈퇴자 제외 |

## 3. (함께 반영 권장 — 미반영分) `DELETE /api/users/me` 5일 보존 정책 #83

> 이전 변경(#83 / PR #84, "회원 탈퇴 A안: 5일 보존 후 완전삭제 + 재로그인 시 새 계정 처리")이
> 아직 노션 명세에 반영되지 않았음. 이번에 함께 반영 권장.

- 탈퇴는 즉시 **soft delete + 익명화**로 처리되고, 남은 access token으로는 더 이상 조회 불가.
- 탈퇴 후 **5일간 데이터 보존**, 이후 스케줄러가 **완전 삭제**.
- 보존 기간 내라도 같은 소셜 계정으로 **재로그인하면 새 계정(재가입)** 으로 처리된다
  (기존 탈퇴 계정을 되살리지 않음).
